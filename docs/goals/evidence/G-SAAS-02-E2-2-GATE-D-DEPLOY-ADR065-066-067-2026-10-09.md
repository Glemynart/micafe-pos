# G-SAAS-02 / M2 / E2.2 — Gate D deploy de notificaciones de solicitudes (2026-10-09)

## Dictamen

Gate D = PASS para el despliegue del codebase `saas-bodega`, limitado a
`micafe-pos-staging`. La notificación push automática requiere todavía la
validación funcional de Gate F; este dictamen no la sustituye.

## Cambios integrados y CI

- PR #503 integró el preflight final de Gate C y ADR-SAAS-067 mediante el merge
  SHA `b708659e06cf56e5be9949948dac4bd28849f25d`.
- El CI post-merge de `main`, run `37903659311`, terminó `success` sobre ese SHA.
- El árbol desplegado coincide con el merge SHA; `firebase.json`,
  `.firebaserc` y `functions-bodega` no difieren del candidato preflight.

## Despliegue controlado

Comando ejecutado con Firebase CLI 15.32.1:

```text
firebase deploy --project=micafe-pos-staging --only functions:saas-bodega --non-interactive --force
```

El CLI reportó `Deploy complete!`: 16 actualizaciones exitosas de Functions
existentes y una creación exitosa; cero eliminaciones. El nuevo trigger es
`notificarSolicitudVentaBodegaPendienteV1`.

## IAM y cambios fuera de alcance

El Admin Activity Log de `micafe-pos-staging` registró un solo `SetIamPolicy`,
el `2026-10-09T08:37:21.668910Z`, asociado al despliegue. Su `policyDelta`
contiene exactamente los tres pares autorizados por ADR-SAAS-066:

| Rol | Principal |
|---|---|
| `roles/iam.serviceAccountTokenCreator` | `service-192423427245@gcp-sa-pubsub.iam.gserviceaccount.com` |
| `roles/eventarc.eventReceiver` | `192423427245-compute@developer.gserviceaccount.com` |
| `roles/run.invoker` | `192423427245-compute@developer.gserviceaccount.com` |

La lectura posterior de IAM confirmó esos tres grants. Se mantienen los grants
de service agents aceptados previamente por ADR-SAAS-067 y el binding anterior
de Firebase Admin. En la ventana del despliegue no se observaron eventos
`EnableService`. El deploy se dirigió solo a `micafe-pos-staging` y al codebase
`saas-bodega`; no se modificaron producción, tenant real, Rules, Secrets, Auth,
Firestore ni datos de negocio.

## Rollback y siguiente validación

El inventario de revisiones anterior al despliegue está capturado en el
[preflight Gate C ADR-065/066/067](G-SAAS-02-E2-2-GATE-C-PREFLIGHT-ADR067-2026-10-09.md).
Si una verificación funcional falla, se restauran las 16 revisiones anteriores
y se retira solo el trigger nuevo si llegó a crearse. Los roles no se retiran
sin comprobar primero que ningún servicio los use.

Gate D acredita el deploy y la salud de configuración. Gate F aún debe probar
en staging la entrega push desde el trigger/outbox, reintentos y replay, pérdida
de respuesta, aislamiento y revocación/restauración, expiración/liberación de
reservas y la matriz integral de PWA, Backoffice y turnos. No se declara Gate F
PASS con esta evidencia.
